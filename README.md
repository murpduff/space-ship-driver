## About

Space Ship Driver is a collection of my procedural terrain and graphics programming work, built in Unity. It covers:

- **Optimized procedural terrain generation** that uses both the CPU (multithreaded Jobs + Burst) and the GPU (compute shaders).
- **Level-of-detail (LOD) algorithms** that let the player see tens of kilometers into the distance.
- **Planets you can explore**: a GPU-generated globe whose data seeds the surface terrain you fly over.
- **Graphics programming**: a Rayleigh-scattering atmosphere, plus lighting and normal maps that add detail without a heavy performance cost.

The next iteration of this work is in **[quad-tree-planet](https://github.com/murpduff/quad-tree-planet)**, a fork of this project that uses a quad-tree LOD system to generate entire to-scale planets the player can explore. It's still a work in progress: so far it focuses only on terrain generation.

## Technical Highlights

### 1. Atmospheric Scattering (Rayleigh)

The atmosphere is a full-screen post-process shader that ray-marches through a spherical atmospheric shell around the planet.

| File | Role |
|---|---|
| [`Assets/Materials/Shaders/AtmosphereShader.shader`](Assets/Materials/Shaders/AtmosphereShader.shader) | Full-screen URP pass: ray-marched in-scattering, optical depth, Beer's-law transmittance, Rayleigh phase function, sun disc, and depth-based blending with the scene |
| [`Assets/Scripts/PlanetGeneration/PlanetManager.cs`](Assets/Scripts/PlanetGeneration/PlanetManager.cs) | Computes the per-channel scattering coefficients from the wavelengths of red, green and blue light and sends the planet/atmosphere radii to all shaders as globals |
| [`Assets/Materials/Shaders/RaySphereIntersection.hlsl`](Assets/Materials/Shaders/RaySphereIntersection.hlsl) | Ray/sphere intersection used to find where each view ray enters and leaves the atmosphere |

**How it works:**

1. **Wavelength-dependent scattering:** Rayleigh scattering strength is proportional to `1 / λ⁴`, so blue light (400 nm) scatters far more than red (700 nm). `PlanetManager` turns this into RGB coefficients:
   ```csharp
   float scatterR = Mathf.Pow(400 / waveLengths.x, 4);   // red   ~700 nm
   float scatterG = Mathf.Pow(400 / waveLengths.y, 4);   // green ~530 nm
   float scatterB = Mathf.Pow(400 / waveLengths.z, 4);   // blue  ~400 nm
   ```
2. **Density falloff:** air density decreases exponentially with altitude (`densityAtPoint`).
3. **Optical depth:** for each sample along the view ray, the shader integrates density toward the sun and back toward the camera (`opticalDepth`).
4. **Transmittance and in-scattering:** Beer's law (`exp(-depth * coefficients)`) controls how much light survives. The light scattered toward the camera is accumulated and weighted by the Rayleigh phase function `3/(16π)·(1 + cos²θ)`.
5. **Day/night:** a smoothstep on each sample point's angle to the sun produces the terminator, which lets stars show through at dusk.

The red sunsets and blue middays come from the physics, they aren't selected.

### 2. Procedural Terrain on the CPU (Jobs + Burst)

| File | Role |
|---|---|
| [`Assets/Scripts/PlanetGeneration/SurfaceTerrainGeneration.cs`](Assets/Scripts/PlanetGeneration/SurfaceTerrainGeneration.cs) | Chunk manager and the Burst-compiled `HeightJob` that builds each terrain mesh |

- **Chunked, infinite-style world:** the terrain is a grid of chunks centered on the player. When the player has moved far enough (`chunkUpdateDst`), the chunk field is rebuilt.
- **Spiral loading:** chunks are generated in a spiral outward from the player, so nearby terrain appears first.
- **Distance-based LOD:** the `LODByDst` animation curve sets each chunk's vertex resolution from its distance. Far chunks use fewer vertices, which is what makes view distances of tens of kilometers possible.
- **Multithreaded mesh generation:** heights, triangles and **analytic normals** (computed from the noise gradient) are calculated in a `[BurstCompile]` `IJobParallelFor`, off the main thread.
- **Object pooling:** inactive chunks go back onto a `Stack` and are reused instead of being destroyed and re-instantiated.
- **Chunk skirts:** an optional ring of vertices along each chunk's edge drops downward to hide cracks between chunks with different LODs.

### 3. Planet Generation on the GPU (Compute Shader)

| File | Role |
|---|---|
| [`Assets/Scripts/PlanetGeneration/TerrainGenCompute.compute`](Assets/Scripts/PlanetGeneration/TerrainGenCompute.compute) | Runs on all 6 faces of a cube-sphere at once, writing into a `Texture2DArray` |
| [`Assets/Scripts/PlanetGeneration/noiseTerrain.hlsl`](Assets/Scripts/PlanetGeneration/noiseTerrain.hlsl) | Layered simplex noise for **height** (R), **humidity** (G) and **temperature** (B): continents, tectonic-style mountain ranges, deserts and polar ice |
| [`Assets/Scripts/PlanetGeneration/PlanetTerrainHandler.cs`](Assets/Scripts/PlanetGeneration/PlanetTerrainHandler.cs) | Allocates the cube-map render texture and dispatches the compute shader |
| [`Assets/Scripts/PlanetGeneration/SamplePlanetaryTerrain.cs`](Assets/Scripts/PlanetGeneration/SamplePlanetaryTerrain.cs) | Uses `AsyncGPUReadback` to read the planet data under the player's entry point and passes it to the surface terrain generator |

This links the two scales of the project. The planet's continents and biomes are generated on the GPU, and the region the player flies into is read back to drive the detailed CPU-generated surface terrain. Note: Currently, biomes are not accounted for in the CPU generated surface terrain. The planetary terrain texture is used as a basis only for the CPU-generated surface terrain height.

---

### 4. Lighting and Normal Maps

| File | Role |
|---|---|
| [`Assets/Materials/Shaders/TerrainShader.shader`](Assets/Materials/Shaders/TerrainShader.shader) | Triplanar-mapped terrain using diffuse and normal **texture arrays**, slope-based material blending, and a distance-faded macro normal layer that breaks up tiling |
| [`Assets/Materials/Shaders/TerrainDetails.hlsl`](Assets/Materials/Shaders/TerrainDetails.hlsl) | Procedural detail normals (e.g. boulders) generated from noise gradients in the shader |
| [`Assets/Editor/TextureArrayCreator.cs`](Assets/Editor/TextureArrayCreator.cs) | Editor tool that packs terrain textures into `Texture2DArray` assets |
| [`Assets/Materials/Shaders/SphereImposter.shader`](Assets/Materials/Shaders/SphereImposter.shader) | Ray-traced ocean sphere with depth-based color, foam and animated normals |

Normal maps and per-pixel lighting add surface detail that would otherwise need far more geometry, which keeps the frame rate high at long view distances.

## Project Structure

```
Assets/
├── Scripts/
│   ├── PlanetGeneration/      # Terrain + planet generation (CPU jobs, GPU compute, noise)
│   ├── ShipBehavior/          # Spaceship movement and editor
│   ├── JetMovement.cs         # Supersonic jet flight model (thrust, lift, roll stability)
│   ├── PlayerCamera.cs        # Mouse-look camera
│   └── ...
├── Materials/Shaders/         # Atmosphere, terrain, ocean and planet shaders (HLSL + Shader Graph)
├── Editor/                    # Texture-array creation tool
├── 3DModels/                  # Spaceship and cockpit models (made in Blender)
├── Inputs/                    # Input System action maps
└── Scenes/SampleScene.unity   # Main scene
```

## Getting Started

### Requirements
- **Unity 6000.2.9f1** (Unity 6), using the **Universal Render Pipeline**
- A GPU that supports compute shaders

### Running the project
1. Clone the repository:
   ```bash
   git clone https://github.com/murpduff/space-ship-driver.git
   ```
2. Open the folder in **Unity Hub** with Unity 6000.2.9f1.
3. Open `Assets/Scenes/SampleScene.unity` and press **Play**.

Flight controls are defined in `Assets/Inputs/JetAction.inputactions` (Unity Input System).
